# Discord Bot

専用チャンネルに評価画像を投稿すると、Botが個体値とPvP順位を返信します。
Discord Gatewayで投稿を受信し、Durable Objectsで接続と処理待ちデータを管理します。
画像認識と順位計算もDurable Objectsで実行します。
GameWithなどの外部チェッカーやBrowser Runは使いません。

## 初回設定

1. [Discord Developer Portal](https://discord.com/developers/applications)でApplicationを作成します。
2. Bot設定でMessage Content Intentを有効にします。これがないと通常の投稿から画像や本文を取得できません。
3. Botトークンを発行し、次のSecretコマンドの入力欄へ直接入力します。
4. OAuth2のURL Generatorで`bot`を選びます。View Channels・Send Messages・Read Message Historyを付けてサーバーへ招待します。
5. 専用のテキストチャンネルを作成し、Botの閲覧・返信を許可します。Discordの開発者モードでチャンネルIDをコピーします。

```sh
npx wrangler secret put DISCORD_BOT_TOKEN
npx wrangler secret put DISCORD_CHANNEL_ID
npm run deploy
npm run bot -- start
npm run bot -- status
```

Botトークンをチャットやリポジトリへ貼り付けないでください。
管理コマンドは`.dev.vars.production`の`APP_PASSWORD`を読みます。公開先を変える場合は`APP_URL`も指定します。
`status`の`connected`が`true`なら接続済みです。起動直後は接続中のため`false`になる場合があります。
停止するときは`npm run bot -- stop`を実行します。停止時に処理待ちデータは削除しません。
`issue`に認証や権限の問題が表示されたら設定を確認し、修正後に`start`を実行してください。
管理APIは利用コードによる認証を必須にしています。Botは設定したチャンネルだけを処理します。

## 使い方と制限

名前と評価バーが見えるPNG・JPEG・WebPを、1枚あたり8MB以下で送ります。
画像は800万画素以下、幅250ピクセル以上、高さ400ピクセル以上に対応します。
複数添付した場合も順番に処理し、画像ごとに番号を付けて返信します。1枚の解析に失敗しても残りを処理します。
返信にはPL50上限の4リーグと進化候補の順位を表示します。上位1〜30位には星を付け、太字で強調します。
上位30位を含む進化候補は、他の進化候補より先に表示します。
名前が同じフォルムを画像から確定できない場合は、フォルム未確定と明記して各候補の順位を表示します。
各フォルムの本体を先に表示し、その後にそれぞれの進化候補を表示します。
読み取った名前と個体値は画像と見比べてください。
誤読した場合は画像を添付し直し、本文を`デルビル 8/3/11`の形式で指定できます。
名前の後の空白は、入力形式の区切りに必要です。
1枚だけ添付した場合は画像認識を省略し、本文の名前と個体値で順位を計算します。
複数添付時は、同じ指定を別の画像へ適用しないよう本文の指定を使いません。修正する画像だけを1枚で再投稿してください。

通常個体の全4,096通りを能力値の積で比較し、同率は同順位にします。
種族値と進化関係は同梱の公開データを使います。固定順位を本番で返す処理はありません。
現在のCPによる参加可否、対戦相性、技は判定しません。
性別・地域・イベントなどの進化条件も判定しないため、進化先は候補として表示します。
返信が長い場合は一部の候補を省略します。フォルムも含めた候補名と個体値を本文に指定し、画像を1枚添付して計算できます。
データの更新手順は[README](../README.md#検証とデータ更新)を参照してください。

接続断後はセッションの復元を試みます。長時間の停止などで復元できない場合、停止中の投稿を取りこぼすことがあります。
処理中を含む待ち行列は最大20枚です。投稿内の全画像が収まらない場合は、その投稿の全画像を受け付けません。
再投稿は20枚以下にしてください。空きが足りない場合の案内は1分に1回までです。
`rejectedMessages`には、受付できなかった投稿数を表示します。
返信の送信前に状態を保存します。送信結果が不明な場合は、二重返信を避けるため自動再送しません。
この件数は`uncertainReplies`で確認できます。返信が届かなかった画像は再投稿してください。
Discordの送信制限では、指定された時間を待ってから再試行します。
送信制限の待機状態と再送可能な状態は同時に保存し、再起動後も未送信の画像を処理します。
処理済みの投稿IDは直近200件を保持します。Botの投稿とWebhookの投稿は無視します。
接続先のチャンネル変更は、保留データの扱いを決める必要があるため管理APIで拒否します。

## 無料枠と構成の選択

Workers Freeを維持します。Browser Runの時間枠は消費しません。
[Durable Objectsの無料枠](https://developers.cloudflare.com/durable-objects/platform/pricing/)は1日13,000GB-sです。
2026-09-14に公式資料を確認しました。常時接続は128MiBを24時間使う計算で10,800GB-sになります。
同じアカウントの他のDurable Objectsも枠を共有します。無料で処理できる枚数は処理時間によって変わります。
上限を超えると処理に失敗します。有料プランへ変更する処理は行いません。

投稿時の即時受付を優先し、定期的なチャンネル確認やスラッシュコマンドは採用しません。
Durable Objectsに接続情報を保存できるため、D1は使いません。
画像認識には既存のTesseract.js Coreと日本語モデルを使います。有料の画像認識APIは追加しません。
画像をメモリ上で展開し、評価バーと文字を読み取ります。画像は保存しません。
名前の位置はHPバーと、その左右の白い余白から決めます。緑の背景をHPバーとして扱わないための確認です。
同時処理を直列化し、文字認識エンジンを再利用します。初期化に失敗した場合は次の要求で作り直します。
画像解析の待機期限は45秒です。期限切れや解析失敗時は順位を計算しません。
画像の通信失敗・タイムアウト・HTTP5xxでは、ダウンロードを1回だけ再試行します。
各試行の待機上限は15秒です。HTTP4xx、リダイレクト、画像サイズ超過では再試行しません。
2回とも通信に失敗した場合は、Discordから画像を取得できなかったと返信します。
ログには失敗の種類と試行回数だけを出します。署名付きURLや画像は記録しません。
本番のDurable Objectのクラス名は保存データの維持のため`RankBrowser`のままですが、ブラウザは起動しません。

### Test decision

- 対応：既存の計算・認証・Gateway・画像認識のテストを再利用。
- 旧サイトのDOMテストを置換し、実画像の結合テストを自前計算へ更新。
- 根拠：計算値を別の候補やPL上限へ対応させる誤りと、旧サービスの結果が残る問題を検出する。
- 画像取得の検証：通信障害後の復帰と再試行の上限を追加。従来の検証は画像サイズとURLの拒否だけが対象だった。
- 再試行しない条件では、取得が1回で終わることと応答の本文を解放することも確認。
- 複数画像の検証：既存のGatewayテストを更新し、全画像の保存・再起動後の再送・一部失敗後の継続を確認。
- 返信の検証：画像ごとの番号と重複防止用の値、1位・30位・31位の表示を追加。従来は単一画像と通常の順位だけを確認していた。
- 名前の位置の検証：緑の背景とHPバーがある画像を追加。従来は切出し位置の誤りを検出できなかった。
- フォルムの検証：既存のOCRテストを更新し、ロコンの両候補と進化先の表示を確認。手動指定では指定したフォルムだけを表示する。

Gatewayの仕様は[Discord公式資料](https://docs.discord.com/developers/events/gateway)を参照してください。
返信の重複防止は[Create Message](https://docs.discord.com/developers/resources/message#create-message)のnonceも使います。
nonceの保持期間は数分のため、永続化した送信状態も合わせて判断します。
